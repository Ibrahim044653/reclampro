Guide d'administration RéclamPro

Ce guide est destiné à l'administrateur système responsable de la configuration, de la maintenance et de la supervision de la plateforme RéclamPro. Les actions décrites ici nécessitent le rôle Administrateur.

1 Gestion des utilisateurs

La gestion des comptes utilisateurs s'effectue depuis la page Utilisateurs de l'interface (/utilisateurs.html), accessible uniquement aux administrateurs.

Créer un compte utilisateur

  1. Accédez à /utilisateurs.html via la sidebar.
  2. Cliquez sur + Ajouter un utilisateur.
  3. Renseignez le nom complet, l'adresse email professionnelle, le rôle (Agent, Superviseur ou Administrateur) et l'équipe d'affectation.
  4. Un mot de passe temporaire est généré automatiquement et envoyé à l'adresse email indiquée. L'utilisateur devra le modifier à sa première connexion.
Astuce : Créez les équipes avant de créer les utilisateurs pour pouvoir les affecter immédiatement à la bonne équipe.

Désactiver un compte

Pour désactiver un compte sans le supprimer (en cas de départ d'un collaborateur) :

  1. Trouvez l'utilisateur dans la liste et cliquez sur son nom.
  2. Dans le panneau de droite, basculez le switch Compte actif en position désactivée.
  3. Confirmez l'action. L'utilisateur ne pourra plus se connecter mais ses données et dossiers sont préservés.
Important : Ne supprimez jamais un compte utilisateur — cela casserait l'historique des actions sur les dossiers. Désactivez le compte à la place.

Changer le rôle d'un utilisateur

Cliquez sur l'utilisateur, puis modifiez le champ Rôle dans le panneau de droite. Le changement prend effet à la prochaine connexion de l'utilisateur (les sessions actives ne sont pas invalidées immédiatement).

Réinitialiser le mot de passe

Cliquez sur l'utilisateur, puis sur Réinitialiser le mot de passe. Un nouveau mot de passe temporaire est généré et envoyé par email. Le MFA n'est pas réinitialisé en même temps — c'est une action séparée.

Réinitialiser le MFA

Si un utilisateur a perdu son téléphone ou son application MFA, cliquez sur Réinitialiser le MFA dans le panneau utilisateur. Au prochain login, un nouveau QR code sera présenté à l'utilisateur pour qu'il reconfigure son application d'authentification.

2 Gestion des équipes

Les équipes structurent le workflow de traitement. Chaque réclamation est affectée à une équipe, et chaque équipe a un superviseur désigné qui reçoit les alertes SLA.

Créer une équipe

  1. Accédez à /utilisateurs.html et cliquez sur l'onglet Équipes.
  2. Cliquez sur + Nouvelle équipe.
  3. Renseignez le nom de l'équipe (ex. "Équipe Bancaire Nord", "Équipe Assurance CIMA").
  4. Sélectionnez le superviseur responsable parmi les utilisateurs ayant le rôle Superviseur ou Admin.
  5. Sauvegardez. L'équipe est maintenant disponible pour l'affectation des agents et des dossiers.

Affecter des agents à une équipe

Deux méthodes possibles :

  • Depuis la fiche utilisateur : sélectionnez l'équipe dans le champ "Équipe" de chaque agent.
  • Depuis la fiche équipe : dans l'onglet Équipes, ouvrez une équipe et utilisez le champ "Membres" pour ajouter plusieurs agents en une fois.
Bonne pratique : Créez au moins une équipe "Défaut" qui reçoit les dossiers non affectés. Cela évite que des réclamations restent sans équipe assignée.

3 Configuration SLA

Les délais SLA (Service Level Agreement) définissent le temps maximum de traitement par niveau de priorité. Ces délais sont conformes aux obligations réglementaires BCEAO.

Critique
24h
Réclamations urgentes avec impact financier immédiat
Urgent
72h
Réclamations importantes nécessitant traitement rapide
Standard
5 j
Réclamations courantes — délai réglementaire BCEAO
Réglementation : Le délai de 5 jours ouvrés pour les réclamations STANDARD est imposé par la BCEAO (Instruction 008). Ne réduisez pas ce délai sans vérification réglementaire, et ne l'augmentez jamais — cela exposerait l'institution à des sanctions.

Modifier les délais SLA

Les délais SLA sont configurés dans les variables d'environnement Vercel :

VariableValeur par défautDescription
SLA_CRITIQUE_HEURES24Délai en heures pour les dossiers CRITIQUE
SLA_URGENT_HEURES72Délai en heures pour les dossiers URGENT
SLA_STANDARD_JOURS5Délai en jours ouvrés pour les dossiers STANDARD

Modifiez ces valeurs dans Vercel (Settings → Environment Variables) puis redéployez.

4 Configuration email SMTP

Le système d'email est utilisé pour les notifications d'alerte SLA, les confirmations aux clients et les réinitialisations de mot de passe.

Variables d'environnement à configurer

VariableExempleDescription
EMAIL_DRIVERsmtpMettre smtp pour l'envoi réel, console pour les tests (logs uniquement)
SMTP_HOSTsmtp.gmail.comServeur SMTP de l'établissement ou fournisseur (SendGrid, Mailgun…)
SMTP_PORT587Port SMTP — 587 (STARTTLS) recommandé, 465 pour SSL direct
SMTP_USERreclamations@mabanque.snCompte SMTP d'envoi
SMTP_PASSWORDapp-password-iciMot de passe SMTP ou App Password (Gmail)
SMTP_FROMRéclamations BCEAO <rec@mabanque.sn>Nom et adresse affichés dans les emails envoyés

Configuration avec Gmail

  1. Activez la vérification en deux étapes sur le compte Gmail de l'établissement.
  2. Accédez à Compte Google → Sécurité → Mots de passe des applications.
  3. Créez un mot de passe d'application pour "RéclamPro".
  4. Utilisez ce mot de passe (16 caractères) comme valeur de SMTP_PASSWORD.
  5. Configurez SMTP_HOST=smtp.gmail.com, SMTP_PORT=587.

Tester la configuration email

Après avoir configuré les variables SMTP dans Vercel, testez en déclenchant manuellement l'endpoint cron (qui envoie des emails) :

# Déclenche un test email via le cron SLA
$ curl -X GET \
  https://votre-app.vercel.app/api/health \
  -H "Authorization: Bearer VOTRE_CRON_SECRET"

Vérifiez ensuite dans les logs Vercel (Dashboard → Logs) que l'email a bien été envoyé sans erreur SMTP.

5 Cron et escalade SLA

L'escalade SLA est automatisée par un cron Vercel qui s'exécute quotidiennement à 7h00 UTC (8h00 WAT). Il identifie les dossiers en risque de dépassement et notifie les superviseurs.

Comportement automatique

  • Dossiers à moins de 24h de l'échéance : notification email envoyée au superviseur de l'équipe assignée.
  • Dossiers avec SLA dépassé : priorité automatiquement remontée à CRITIQUE, notification email superviseur et admin.
  • Toutes les escalades sont loggées dans la table interactions avec le type ESCALADE_SLA.

Tester le cron manuellement

Pour vérifier le fonctionnement du cron sans attendre l'exécution automatique :

# Test manuel du cron SLA — remplacez par votre URL et CRON_SECRET
$ curl -X GET \
  https://votre-app.vercel.app/api/cron/sla-check \
  -H "Authorization: Bearer VOTRE_CRON_SECRET" \
  -v

La réponse attendue est 200 OK avec un corps JSON indiquant le nombre de dossiers escaladés :

{ "escalades": 3, "notifications_envoyees": 2, "status": "ok" }
Logs Vercel : Les détails de chaque exécution cron sont visibles dans Vercel Dashboard → votre projet → Logs. Filtrez par /api/cron/sla-check pour voir uniquement les exécutions cron.
Si le cron n'envoie pas d'emails : Vérifiez que EMAIL_DRIVER=smtp (pas console) et que les variables SMTP sont correctement configurées. En mode console, les emails apparaissent dans les logs Vercel mais ne sont pas réellement envoyés.

6 Exports réglementaires

Les exports réglementaires permettent de générer les états statistiques requis par la BCEAO et la Commission CIMA. Ils sont accessibles depuis la sidebar sous "Reporting".

Formats disponibles

FormatUsageContenu
CSV Import dans Excel, traitement analytique Tous les champs de chaque dossier, séparateur virgule, encodage UTF-8
XLSX Rapport BCEAO format standard Tableur Excel formaté avec en-têtes, colonnes conformes au modèle BCEAO, totaux automatiques
PDF Rapport officiel, archivage Rapport formaté avec logo, période, métriques agrégées et liste des dossiers

Procédure d'export

  1. Accédez à la page Reporting via la sidebar (/reportings.html).
  2. Sélectionnez la période (trimestre, mois ou plage de dates personnalisée).
  3. Filtrez si nécessaire par entité, type de réclamation ou statut.
  4. Cliquez sur le bouton du format souhaité : CSV, Excel (XLSX) ou PDF.
  5. Le fichier est téléchargé automatiquement dans votre navigateur.
Fréquence recommandée : Générez et archivez un rapport XLSX ou PDF chaque trimestre pour satisfaire aux obligations de reporting trimestriel BCEAO. Conservez ces fichiers sur un espace sécurisé interne.

7 Portail client public

Le portail client est une interface web publique qui permet aux clients de consulter l'état de leur réclamation sans créer de compte. Il est accessible à l'URL /portail.html.

Fonctionnement

  • Le client saisit sa référence de dossier (ex. REC-2024-00123) et son adresse email.
  • Le système vérifie que l'email correspond au client enregistré pour ce dossier (protection anti-consultation non autorisée).
  • Si la vérification est réussie, le client voit le statut actuel, la date de réception et la dernière mise à jour.
  • Si le dossier est résolu ou clos, la réponse de l'établissement est affichée.

Informations non visibles par le client

  • Les commentaires internes des agents
  • Le nom des agents assignés
  • Les pièces jointes internes
  • L'historique complet des actions

URL du portail

L'URL publique à communiquer aux clients est :

https://votre-app.vercel.app/portail.html
Astuce : Ajoutez un lien vers ce portail sur le site internet de votre établissement et dans vos emails de confirmation automatique. Les clients pourront ainsi suivre leurs dossiers de façon autonome, réduisant les appels entrants.

8 Conservation des données

La politique de conservation des données est définie par la réglementation BCEAO (Règlement RG011) et les bonnes pratiques de protection des données personnelles.

Règles de conservation

Type de donnéeDurée de conservationAction à l'échéanceBase légale
Dossiers de réclamations 5 ans minimum Archivage (statut ARCHIVÉ, inaccessible aux agents) BCEAO RG011 art. 14
Données personnelles clients 10 ans maximum Anonymisation (suppression des données PII chiffrées) BCEAO RG011 + RGPD CEDEAO
Logs d'interactions 5 ans Archivage avec le dossier BCEAO — traçabilité
Pièces jointes 5 ans Suppression physique après validation juridique Aligné sur le dossier

Archivage manuel

Pour archiver un dossier manuellement avant l'échéance automatique :

  1. Ouvrez le dossier en vue détail.
  2. Changez le statut à ARCHIVÉ via le menu déroulant.
  3. Le dossier n'apparaît plus dans les listes actives mais reste consultable avec le filtre "Archivé".
Interdiction : Il est strictement interdit de supprimer physiquement un dossier ou des données client avant le délai légal de 5 ans. Cette action exposerait l'établissement à des sanctions BCEAO lors d'un audit. L'interface n'autorise pas la suppression pour cette raison.

Anonymisation à 10 ans

L'anonymisation des données personnelles après 10 ans est une opération à effectuer manuellement via l'API (ou à planifier comme un cron annuel). Elle supprime les colonnes PII chiffrées (nom_chiffre, email_chiffre, telephone_chiffre) tout en conservant le dossier et ses métadonnées.

9 Ajout de CRON_SECRET dans Vercel

Le CRON_SECRET est indispensable pour sécuriser l'endpoint de cron SLA. Sans lui, n'importe qui pourrait déclencher l'escalade SLA depuis l'extérieur. Voici la procédure complète d'ajout.

Via la CLI Vercel (recommandé)

  1. Installez la CLI Vercel si ce n'est pas fait : npm install -g vercel
  2. Connectez-vous : vercel login
  3. Générez un secret sécurisé :
# Génération d'un secret de 32 caractères hexadécimaux
$ openssl rand -hex 16
a3f8b2c1d9e4f5a6b7c8d9e0f1a2b3c4
  1. Ajoutez le secret à Vercel :
# Ajouter CRON_SECRET à toutes les environments (production, preview, dev)
$ vercel env add CRON_SECRET production
? What's the value of CRON_SECRET? a3f8b2c1d9e4f5a6b7c8d9e0f1a2b3c4

# Répétez pour preview et development si nécessaire
$ vercel env add CRON_SECRET preview
  1. Redéployez l'application pour que le changement prenne effet : vercel --prod ou déclenchez un déploiement depuis le dashboard Vercel.

Via le Dashboard Vercel

  1. Ouvrez votre projet sur vercel.com.
  2. Allez dans Settings → Environment Variables.
  3. Cliquez sur Add New, entrez CRON_SECRET comme nom et collez votre valeur générée.
  4. Cochez les environnements cibles (Production, Preview).
  5. Sauvegardez, puis redéployez depuis l'onglet Deployments.
Vérification : Après redéploiement, testez en appelant /api/health — si la réponse est 200, le déploiement est opérationnel. Testez ensuite le cron avec le header Authorization: Bearer VOTRE_CRON_SECRET.

10 Dépannage

Cette section recense les problèmes fréquents et leurs solutions.

Logs Vercel

Les logs en temps réel sont disponibles dans Vercel Dashboard → votre projet → Logs. Filtrez par :

  • Error : pour voir uniquement les erreurs
  • /api/ : pour filtrer les appels API
  • /api/cron/ : pour les logs cron

Vérifier l'état du service

# Health check — doit retourner 200 avec {"status": "ok", "db": "connected"}
$ curl https://votre-app.vercel.app/api/health

Problèmes courants et solutions

SymptômeCause probableSolution
Login impossible, erreur 500 Base de données inaccessible ou DATABASE_URL incorrecte Vérifier /api/health, contrôler la variable DATABASE_URL dans Vercel
Token JWT invalide après déploiement JWT_SECRET a changé — les anciens tokens sont invalidés Normal si la clé a changé. Les utilisateurs doivent se reconnecter. Ne changez JWT_SECRET qu'en cas de compromission.
Les emails ne sont pas envoyés EMAIL_DRIVER=console ou configuration SMTP incorrecte Vérifier EMAIL_DRIVER=smtp et tester les credentials SMTP avec un client mail
Le cron ne s'exécute pas Plan Vercel Hobby (pas de cron) ou CRON_SECRET manquant Vérifier que le plan Vercel supporte les crons, et que CRON_SECRET est configuré
Données de démo absentes SEED_AT_STARTUP=false ou seed déjà exécuté Mettre temporairement SEED_AT_STARTUP=true et redéployer. Remettre à false après.
Pièces jointes perdues après redéploiement Vercel utilise /tmp ephémère — les fichiers sont perdus à chaque déploiement Configurer un bucket de stockage persistant (Vercel Blob, AWS S3 ou Cloudflare R2) pour UPLOAD_DIR
MFA ne fonctionne plus (codes refusés) Décalage de l'horloge système ou utilisateur Synchroniser l'horloge de l'appareil mobile du l'utilisateur (paramètre "heure automatique"). Si le problème persiste, réinitialiser le MFA de l'utilisateur.

Réinitialiser le seed de données

# Pour réinitialiser les données de démo :
# 1. Mettre SEED_AT_STARTUP=true dans Vercel env vars
# 2. Redéployer
$ vercel env add SEED_AT_STARTUP production
? Value: true
$ vercel --prod

# 3. Après redéploiement, remettre à false
$ vercel env add SEED_AT_STARTUP production
? Value: false
$ vercel --prod
Attention : Le seed écrase les données existantes en production. N'activez SEED_AT_STARTUP=true qu'en environnement de démo ou de développement. En production réelle, ne l'activez jamais.
